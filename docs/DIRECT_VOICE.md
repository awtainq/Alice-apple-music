# Apple Music по голосу без имени навыка

## Как работает

На Станции 2 с root-доступом процесс Алисы публикует финальный текст распознанной команды в локальный TCP-канал `127.0.0.1:9875`. Служба SSH на VPS пробрасывает этот канал только на свой loopback `127.0.0.1:19875`. `voice.py` читает события, отбирает музыкальные фразы и вызывает защищённый API своего плеера. Новые процессы на колонке, кроме уже установленного SSH, не нужны. Docker не нужен. Для принятых музыкальных команд мост останавливает текущий диалог Алисы через локальный IPC, чтобы она не ждала продолжения и не открывала прежний навык.

Механизм и формат канала описаны в проекте **Yandex Station Extended — Марк Писаренко**, [рецепт Spotify](https://hackalice.me/recipes/spotify/), [исходный alice-text.c](https://github.com/Marker284/yandex-station-extended/blob/main/contrib/station2-media/build/voice/alice-text.c), лицензия [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Здесь реализован отдельный Python-клиент, адаптированный к существующему плееру Apple Music на VPS. Проверенная версия источника: `930a0ffa947d82545089470670609fd20b201a68`.

## Команды

Поиск музыки и запрос названия произносятся с обращением «Алиса». С флагом `--spotter-ssh` поддерживаются также короткие управляющие слова без обращения: «дальше», «назад», «пауза», «стоп», «хватит», «играй», «продолжай».

| Фраза | Действие |
| --- | --- |
| Включи песню Babydoll Dominic Fike | Одна песня, затем рекомендации |
| Включи Noize MC | Поиск; точное совпадение исполнителя включает список его песен |
| Включи исполнителя Noize MC | Песни исполнителя |
| Поставь альбом Nevermind Nirvana | Треки найденного альбома по порядку |
| Включи плейлист Chill | Найденный плейлист из каталога Apple Music |
| Включи музыку / мою музыку | Песни из личной медиатеки Apple Music |
| Дальше / следующая песня | Следующий трек |
| Назад / предыдущая песня | Предыдущий трек |
| Пауза / продолжай | Пауза и продолжение |
| Включи похожие | Рекомендации по текущему треку |
| Что за песня сейчас играет | Название и исполнитель через локальную озвучку Алисы |

Короткие управляющие команды принимаются, если последний поток на колонке принадлежит нашему плееру, либо в течение часа после успешной музыкальной команды. Запрос названия также работает при наличии сохранённого текущего трека. После перезапуска голосового моста сначала назовите песню. Состояние очереди самого плеера сохраняется между перезапусками.

Для альбома, исполнителя, медиатеки или плейлиста загружается до 500 уникальных доступных треков. После списка включаются рекомендации. Локальные загрузки в iCloud без каталожного ID пропускаются. «Моя музыка» означает медиатеку, а не отдельный список избранного. Плейлисты ищутся в каталоге, поиск личных закрытых плейлистов пока не добавлен.

Это голосовое управление плеером на VPS. Появление Станции среди AirPlay-устройств в приложении Apple Music потребует отдельного AirPlay-приёмника; данный модуль его не устанавливает.

## Требования

- Работающий нативный плеер и его личная конфигурация.
- Станция 2 с уже настроенным root и SSH, проверенный IP-адрес.
- VPS с доступом к домашней сети через VPN и обратным маршрутом для аудио.
- OpenSSH client на VPS, Python и зависимости основного плеера.
- Прямой режим не требует навыка, проекта Google Cloud или подписки Pub/Sub: плеер запускается с `--no-cloud`. Название произносится через локальный `START_VOCALIZE`.

Получение root — отдельная операция. [Описание автора](https://hackalice.me/start/root/) включает сброс и повторную привязку. Этот комплект сам не меняет прошивку, DNS, обновления или настройки SSH колонки.

## Установка поверх Linux-службы

1. Скопируйте обновлённые `apple.py`, `engine.py`, `service.py`, `voice.py` в `/opt/alice-music/app`. Сделайте резервную копию прежнего кода и конфигурации.
2. Обновите `station_host` в личном `config.json`, если адрес колонки изменился. Закрепите адрес в DHCP домашнего роутера либо следите за его изменениями.
3. Скопируйте `deploy/voice_ssh_config.example` в `/var/lib/alice-music/private/voice_ssh_config`, укажите адрес и способ входа своей колонки. Файл и ключи доступны только `alice-music` с правами `600`.
4. Добавьте **проверенный** SSH host key своей колонки в `/var/lib/alice-music/private/station_known_hosts`. Сверьте отпечаток через уже доверенный SSH/ADB; не отключайте проверку host key.
5. Проверьте вход от пользователя `alice-music`, затем скопируйте оба unit-файла `deploy/alice-music-voice*.service` в `/etc/systemd/system/`.
6. Для режима без навыка создайте `/etc/systemd/system/alice-music.service.d/`, скопируйте туда `deploy/direct-voice.conf.example` под именем `direct-voice.conf`. Укажите в личном `config.json` значение `"open_skill_on_start": false`, а для короткой задержки `"voice_start_delay": 0.2`. При `--no-cloud` облачные поля конфигурации и файл ключа Pub/Sub не используются.
7. Отключите или переименуйте голосовые фразы только собственных музыкальных сценариев из [прежнего способа](VOICE_SHORTCUTS.md). Иначе сценарий и новый мост могут одновременно выполнить одну команду. Сохраните определения для отката. Полное обращение к навыку остаётся доступно.

```sh
sudo systemctl daemon-reload
sudo systemctl restart alice-music
sudo systemctl enable --now alice-music-voice-tunnel alice-music-voice
sudo systemctl status alice-music-voice-tunnel alice-music-voice
sudo journalctl -u alice-music-voice -n 30 --no-pager
```

В примерах tunnel требует `alice-music-vpn.service`. Если плеер расположен дома и VPN не нужен, адаптируйте зависимости unit-файла. Порты `19875`, `9875`, `2222` и `5555` не нужно открывать в публичный интернет.

## Ограничения и приватность

После принятия музыкальной команды мост отправляет `STOP_CONVERSATION`, `CANCEL_DIALOG_AND_CLEAR_QUEUE` и `STOP_TTS` в локальный канал. Это прерывает штатный диалог только для отобранных музыкальных фраз. Плеер ждёт свободного состояния Алисы и запускает Apple Music. Задержка зависит от сети и подготовки аудио; уже начавшийся ответ может прозвучать частично. Формат неофициальный, совместимость с другими прошивками не гарантируется.

По SSH через VPN передаётся распознанный текст, включая немузыкальные фразы. Они отбрасываются обработчиком и не записываются в журнал; сырое аудио мост не получает. В журнале остаются типы выполненных музыкальных действий, ошибки и метаданные играющего трека. В режиме `--no-cloud` облачный навык не участвует ни в поиске, ни в озвучивании названия.

Таймеры, свет, громкость и другие распознанные немузыкальные команды остаются штатной Алисе. Фильтр осторожный, но не может безошибочно различить любую пользовательскую команду умного дома и название песни. Для песен с таким названием используйте явное «включи песню …».

## Проверка и откат

Проверьте на колонке запуск конкретной песни, два переключения, паузу, продолжение и название. Дополнительно проверьте таймер, управление светом и громкость. Наличие соединения IPC и прохождение тестов кода сами по себе не подтверждают голосовое воспроизведение.

```sh
sudo systemctl disable --now alice-music-voice alice-music-voice-tunnel
```

После отключения восстановите прежние музыкальные сценарии из сохранённых определений. Основной плеер продолжит работать. Для возврата к облачному навыку удалите drop-in `direct-voice.conf`, выполните `systemctl daemon-reload` и перезапустите плеер; затем восстановите нужные музыкальные сценарии. Удалять прошивку, сбрасывать Станцию или останавливать основной плеер для отката моста не требуется.

На домашней Станции 2 пользователь подтвердил прямое озвучивание названия и команды «продолжай» → «дальше» без открытия навыка. Ожидание программных событий TTS пока не подтверждает завершение: отсутствие события не означает отсутствие звука.

## Короткие команды без обращения

Они обрабатываются отдельной моделью command spotter и не приходят в обычном потоке распознанных фраз. Флаг `--spotter-ssh` добавляет SSH-подключение, которое читает только новые строки `Command phrase spotted:` из `maind.log`, с поддержкой ротации файла. Фильтрация выполняется на колонке; история журнала и остальные строки не передаются. Громкость остаётся штатной Алисе.

Если у плеера сохранён текущий трек, короткие музыкальные команды направляются в его очередь, даже когда встроенный плеер успел запустить Яндекс Музыку. Без сохранённой очереди они остаются штатными. Одна команда, пришедшая по двум каналам, не выполняется дважды. SSH-настройки берутся из `private/voice_ssh_config`, если файл существует; иначе используются адрес из `station_host`, порт `station_ssh_port` (по умолчанию 2222) и проверенный `station_known_hosts`.

Пользователь подтвердил переключение Apple Music словом «дальше» без обращения.
